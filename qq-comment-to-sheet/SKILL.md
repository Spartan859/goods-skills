# QQ 评论排单转表格

将带有时间戳、用户名和购买指令的评论记录转换为“商品 × 九槽位”的 Markdown 排单表。

## 输入

接受以下任一输入：

- 文本记录，每条包含时间戳、用户名和评论内容。
- 评论截图；先逐条读取时间戳、用户名和评论内容，再进行分配。
- 用户提供的自定义映射，例如“花丸的别名是丸”。

如果时间戳、用户名或购买指令无法辨认，停止分配并指出缺失的记录。不要猜测或补造数据。

## 商品与槽位

默认映射：

| 全称 | 简称 |
| --- | --- |
| 千歌 | 千 |
| 曜 | 曜 |
| 梨子 | 梨 |
| 花丸 | 丸 |
| 露比 | 露 |
| 善子 | 善 |
| 黛雅 | 黛 |
| 鞠莉 | 鞠 |
| 果南 | 南 |

商品固定按“千、曜、梨、丸、露、善、黛、鞠、南”排序。每个商品有 9 个槽位，未出现的商品也必须保留完整空行。

用户提供的自定义映射优先于默认映射。按别名长度从长到短替换，避免短别名覆盖长别名。若同一别名映射到多个简称，停止并请求用户确认，不要自行选择。

## 解析规则

1. 先标准化商品名，再解析数量和优先级。
2. 将“两个简称加一个数量词”拆成两个请求。例如：
   - `善梨凹` → `善凹`、`梨凹`
   - `千曜2` → `千2`、`曜2`
3. 支持以下请求形式：
   - `商品n`：占用该商品连续 n 个槽位，n 必须是大于 0 的整数。
   - `商品凹`：占用处理到该请求时该商品的全部剩余槽位。
   - `提商品n` 或 `提商品凹`：与上述规则相同，但属于优先请求。
4. 一条评论包含多个请求时，每个请求独立分配。例如 `千1 (提善1)` 表示一个普通“千1”请求和一个优先“善1”请求。
5. 忽略 `tt`、纯标点、纯空白和明确的非下单闲聊。看起来像下单但无法解析的内容必须停止并请求确认。
6. 同一用户可占用多个槽位。超出剩余库存的部分不写入表格。

## 用户名

用户名单独取评论记录的用户名列。若文本行把用户名与评论写在一起，按第一个空格切分，只保留第一个子串作为用户名。

示例：`AB 黛凹` 中，用户名是 `AB`，请求是 `黛凹`。

## 分配顺序

1. 先分配所有带“提”的请求。
2. 再分配其余请求。
3. 两个分组内部都按时间戳从早到晚排序。
4. 时间戳相同时，保留输入记录中的先后顺序；若截图的纵向顺序无法判断，停止并请求确认。

逐条顺序分配。“凹”只拿该请求处理时对应商品的剩余槽位，不影响其他商品。

## 输出

输出一个 Markdown 表格：

```markdown
| 商品 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 千 |  |  |  |  |  |  |  |  |  |
| 曜 |  |  |  |  |  |  |  |  |  |
| 梨 |  |  |  |  |  |  |  |  |  |
| 丸 |  |  |  |  |  |  |  |  |  |
| 露 |  |  |  |  |  |  |  |  |  |
| 善 |  |  |  |  |  |  |  |  |  |
| 黛 |  |  |  |  |  |  |  |  |  |
| 鞠 |  |  |  |  |  |  |  |  |  |
| 南 |  |  |  |  |  |  |  |  |  |
```

格式要求：

- 单元格只写用户名；空槽位留空，不填写“空”或其他占位符。
- 始终输出全部 9 个商品行和 9 个槽位。
- 发生超售时，在表格后追加一行：`超售未分配：用户名-商品×数量；...`。
- 没有可分配数据时，只说明原因并请求有效输入，不输出伪造表格。

具体输入与预期输出见 [worked-examples.md](references/worked-examples.md)。
