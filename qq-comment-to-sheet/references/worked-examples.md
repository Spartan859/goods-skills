# QQ 评论排单转表格：完整示例

## 默认配置也必须确认

当资料没有明确商品集合或槽位数时，可以提出默认配置：

- 商品：千、曜、梨、丸、露、善、黛、鞠、南
- 商品行数：9
- 每商品槽位：9

仍需询问用户是否按该配置生成。用户确认后才能继续。

## 示例一：确认默认配置后的优先单与超售

用户确认使用默认的 9 个商品、每商品 9 个槽位。

输入：

```text
09:01 | AB | 千2
09:02 | CD | 提善1
09:03 | EF | 千3
```

处理过程：

1. 优先分配 `提善1`，CD 占用“善”的槽位 1。
2. 再按时间分配普通请求：AB 占用“千”的槽位 1 至 2，EF 占用“千”的槽位 3 至 5。

预期输出：

| 商品 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 千 | AB | AB | EF | EF | EF |  |  |  |  |
| 曜 |  |  |  |  |  |  |  |  |  |
| 梨 |  |  |  |  |  |  |  |  |  |
| 丸 |  |  |  |  |  |  |  |  |  |
| 露 |  |  |  |  |  |  |  |  |  |

## 示例二：可变商品行数和槽位数

用户资料确认：

- 商品顺序：千、善、南
- 商品行数：3
- 每商品槽位：4

输入：

```text
10:00 | AB | 千2
10:01 | CD | 提善1
10:02 | EF | 千3
```

预期输出：

| 商品 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- |
| 千 | AB | AB | EF | EF |
| 善 | CD |  |  |  |
| 南 |  |  |  |  |

尾部：

```text
超售未分配：EF-千×1
```

## 示例三：“凹”使用已确认槽位数

如果用户已确认 `slot_count=4`，则 `善凹` 占用善的槽位 1 至 4；不能仍按默认的 9 个槽位处理。
