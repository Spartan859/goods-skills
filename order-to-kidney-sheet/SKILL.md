# 排表/肾表 XLSM 生成

将已经结构化的排表或肾表数据转换为宏兼容的 `.xlsm`。工作簿包含上半部排表、下半部肾表和原汇总宏。

原始 QQ 抢单评论不在此技能内解析。遇到未排单的评论文本时，先使用 `qq-comment-to-sheet` 生成排表。

## 生成前必须确认表参数

在生成工作簿前，先确定并展示：

1. `source_mode`：`arrangement` 或 `kidney`。
2. `allocation_count`：上半部配位列数，必须是大于 0 的整数。
3. 排表商品清单及行顺序；直接肾表模式下说明排表将留空。
4. 价格信息类型：固定价格，或单价、汇率、调价。

优先从用户资料推断：

- 表头中的“第1配”至“第N配”可推断候选 `allocation_count=N`。
- 表格列数、截图列数或最长的配位数组可用于候选值。
- 商品行和顺序从排表读取。
- 价格公式或明确价格从资料读取。

无法推断时使用默认值：

- `allocation_count`：10。
- 排表商品清单：没有默认商品；以用户资料或用户补充为准。
- 直接肾表模式：排表数据留空，但配位列数仍按已确认值生成空白表头。

**无论参数是推断还是默认，都必须向用户说明依据并询问确认。** 用户确认前不得运行生成脚本。若用户在同一条消息中已经明确给出并确认这些参数，可直接使用该确认结果。

确认示例：

> 我从资料中识别到 6 个商品和 12 个配位；若资料不足，将采用默认的 10 个配位。是否按该配置生成？

## 输入

支持表格文件、粘贴的文本表格或图片。逐项读取：

- 排表：商品名、已确认配位数的槽位、单价、汇率、调价或固定价格。
- 肾表：CN、国际金额、可选点数。
- 用户明确给出的目标配列数。

不要猜测缺失或模糊的 CN、金额、商品或槽位。发现歧义时，列出具体行和字段并停止生成。

## 规范化数据

将已确认的结果写入临时 JSON，字段和校验规则见 [input-schema.md](references/input-schema.md)。

排表模式要点：

- `allocation_count` 与用户确认值一致。
- 每个商品的 `allocations` 长度不得超过 `allocation_count`；不足部分按空槽位补齐。
- 有占用的商品必须提供固定 `price`，或同时提供 `unit_price` 与 `exchange_rate`。
- `adjustment` 可选，默认 0。
- 价格公式为 `单价 × 汇率 + 调价`。

直接肾表模式要点：

- 只提供 `kidney_rows`，不要提供排表商品或价格。
- `amount` 映射为`应付`。
- 未提供 `points` 时保留空单元格。
- 重复 CN 按首次出现顺序聚合并求和。
- 排表数据行留空，但表头仍生成 `第1配` 至 `第allocation_count配`。

## 依赖

生成脚本需要 Python 3.10+、`openpyxl` 与 `Pillow`。先用 `python3 -c "import openpyxl, PIL"` 检查运行环境。

## 生成工作簿

在技能目录运行：

```bash
python3 scripts/build_order_kidney_workbook.py \
  --input normalized.json \
  --output "标题-排表-肾表.xlsm"
```

直接肾表模式的推荐输出名称为 `标题-肾表.xlsm`。未提供标题时分别使用：

- `排表-肾表.xlsm`
- `肾表.xlsm`

生成器自动使用 `assets/order-kidney-template.xlsm`，保留表格样式、价格公式和汇总宏。脚本为兼容旧数据将缺省 `allocation_count` 解释为 10，但技能调用流程仍必须先向用户确认实际值。

## 二维码选择

生成工作簿前，按以下顺序决定是否加入二维码：

1. 先读取本地记忆，查找 `order-to-kidney-sheet` 的默认二维码路径。
2. 如果本地记忆提供了有效图片，且用户没有提供新二维码、也没有明确要求不要二维码，则默认使用该本地图片，并写入 `qr_image`。
3. 如果本地记忆没有默认值或默认文件不存在，询问用户是否需要二维码。
4. 用户需要时，请用户提供二维码图片；用户不需要时省略 `qr_image`。
5. 用户当次提供的二维码覆盖本地记忆默认值。用户明确不要二维码时不得添加。

二维码放在肾表右侧，锚定在肾表标题所在行。二维码图片只用于本地生成结果，不得提交到公开仓库、公开聊天或第三方服务。

## 汇总语义

排表模式的肾表复刻原汇总宏：

1. 按第1配至第 `allocation_count` 配的列顺序，再按商品行顺序扫描。
2. CN 首次出现时建立肾表行。
3. 应付为所有占用槽位对应价格之和，保留计算精度并显示两位小数。
4. 点数为占用槽位数量。

直接肾表模式仍保持一行一个 CN。若输入已含点数则累加，全部未提供时保持空白。

## 输出验收

生成后至少确认：

- 文件为有效 `.xlsm`，并包含 `xl/vbaProject.bin`。
- 上半部包含 `第1配` 至 `第allocation_count配`，下半部包含 `CN、应付、点数`。
- 排表 Table 和肾表 Table 的范围覆盖全部数据且互不重叠。
- 顶部“排表”和底部“肾表”标题均使用合并单元格，并水平、垂直居中。
- 若未选择二维码，工作簿不得含示例图片；若选择二维码，应只含用户提供的或本地记忆确认的二维码。
- 价格公式存在，OpenXML 压缩结构完整。

宏启用文件打开时可能触发 Excel 安全提示。只使用本技能内置且已审阅的汇总宏，不要执行来源不明的宏。

完整输入和处理示例见 [examples.md](references/examples.md)。
